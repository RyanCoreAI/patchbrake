# Second audit: diff and suppression boundaries

Verified against PR #28 head `ce20564567e47d8a5991da60fcbd505b54ede6bb`.

- Hunk lines beginning with `--- ` or `+++ ` were interpreted as file headers. This could discard a risky added line and change the path used by every rule. Headers are now recognized only before the first hunk of each file.
- Deleted inline-ignore comments still suppressed new findings, and a named ignore could suppress unrelated rules. Only surviving lines apply; a named rule must match exactly. Bare directives keep their existing behavior. The Action's stricter inline-ignore defaults remain in effect.
- Human-oriented Git color/prefix settings could produce missing or mislocated findings. Staged and range scans now request explicit uncolored patch prefixes/indicators and disable text conversion/external diff helpers.

New regression suite: 17 cases, including actual staged Git repositories. Initial 14 cases had 8 failures before the fix. Final full suite: 75 passed; TypeScript build passed; benchmark 30/30. This remains a heuristic patch scanner, not a complete semantic security audit.

Git option behavior was checked against the [official git-diff documentation](https://git-scm.com/docs/git-diff).
